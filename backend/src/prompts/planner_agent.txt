Batch schema (R = required, O = optional, omit = not used):
- data: {"batch_name": string R, "phases": phase[] R}; strict JSON, at most {max_plan_steps} total steps.
- phase: {"sequence": integer R, "steps": step[] R}; sequences start at 1. Phases run sequentially; steps run in parallel.
- step common: `id` R and unique, `action` R, `task` O, `uses` O (earlier-phase IDs only).

| step action | required | optional | omit |
|---|---|---|---|
| armory_call | resource_type (`tool` or `subagent`), name, parameters | task, uses | child_calls |
| spawn_children | child_calls (`[{"task": string, "parameters": object O}]`) | task | resource_type, name, parameters, uses |
| collect_child | parameters.child_agent_id | task | resource_type, name, child_calls, uses |
| context_select | parameters.key | parameters.from_token, parameters.to_token, task | resource_type, name, child_calls, uses |
| ask_user | parameters.question | parameters.options, task | resource_type, name, child_calls, uses |
| finish | parameters.answer | task | resource_type, name, child_calls, uses |

Execution constraints:
- Use exact Armory names; never invent resources or results.
- Only independent armory_call steps may share a phase. ask_user, finish, context_select, and mutating/confirmation steps run alone.
- End the batch after spawn_children, context_select, or calls whose results are needed. Replan from returned results instead of guessing or repeating completed work.
- If context_selection_summary.loop_detected is true, do not request repeated key/range windows; pick a new range or finish with explicit limits.
