Plan rules:
- Return up to {max_plan_steps} steps.
- Use ordered phases; phases are sequential, steps within a phase are parallel.
- Every phase has consecutive integer sequence starting at 1, and a nonempty steps array.
- Every step has a unique id, action, name, task, parameters object, uses array (empty if none), and child_calls array (empty if none).
- Actions: tool_call, agent_call, spawn_children, collect_child, context_select, ask_user, finish.
- `steps_json` must be a JSON object with top-level key `phases`.
- Do not wrap `steps_json` in CDATA, markdown fences, or any prose.
- `steps_json` must be parseable by strict JSON parsers:
  - Escape newlines inside strings as `\\n`.
  - Escape inner quotes inside strings as `\\"`.
  - Do not include trailing commas.
  - Do not include comments.
- Required parameter keys by action:
  - ask_user -> parameters.question (non-empty string). Do NOT use parameters.prompt.
  - finish -> parameters.answer (string).
  - context_select -> parameters.key (string).
  - collect_child -> parameters.child_agent_id (string) when name is not provided.
  - spawn_children -> child_calls must be a non-empty array.
- To run children in parallel, use ONE spawn_children step containing all child task objects in child_calls.
- Each child_calls item must be an object with a non-empty task. Do not use strings and do not invent child_agent_id values.
- A plan containing spawn_children MUST end immediately after that spawn_children phase. Do not plan collect_child or finish yet; runtime-generated child IDs will be available when the agent replans.
- If execution_history already contains child_agent entries, NEVER spawn replacements. Collect pending child IDs, or use context_select for existing execution_memory keys.
- If execution_history/execution_memory_index already contain completed data for this turn, prefer context_select + synthesis over repeating tool/subagent calls.
- execution_memory_index lists every stored key and description. Values are available only through context_memory; use context_select when a required range is absent or incomplete.
- Do not add planning/decomposition tool steps. Planning is your job; only call exact tool names listed in Armory.
- tool_call name must be an available tool; agent_call name must be an available subagent.
- uses may reference IDs from earlier phases only. If you need a result to fill an argument, plan a later round after reading it; do not guess values.
- Parallel phases (more than one step) may contain only independent tool_call/agent_call steps. Put confirmation-requiring tools and mutating actions alone.
- Every context_select must be alone in its own sequential phase. After the last context_select, stop the plan so the agent can replan with the loaded values.
- ask_user must be alone in its phase. finish must be alone in the final phase, with parameters.answer containing a response you can write now, without future tool results.
- For tasks requiring tool results not yet known, stop after gathering data. The agent will replan with the results.
- Keep steps minimal, use only armory resources, and give no imagined results.
